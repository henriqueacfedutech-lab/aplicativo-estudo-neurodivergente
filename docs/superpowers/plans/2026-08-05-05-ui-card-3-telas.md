# UI do Card em 3 Telas (Plano 5/5) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Juntar tudo dos Planos 1-4 numa tela navegável: diagrama+teoria → problema resolvido → problema independente (com correção), acessível a partir da sessão de estudo (spec, Seção 8, composição A).

**Architecture:** Uma nova `<section class="screen" id="screen-ficha-ia">` com um único container dinâmico (`#fia-conteudo`) que troca de conteúdo conforme uma variável de estado local (`fiaTela = 1|2|3`), no mesmo padrão de tela única dinâmica já usado no Estúdio de Diagramas existente (`#est-preview`, linha ~382). `abrirFichaIA(discId, topico)` é o ponto de entrada, chamado a partir de um novo botão na tela de sessão — mesmo padrão de `abrirEstudio`.

**Tech Stack:** JS vanilla, reaproveitando `gerarFichaIA`/`gerarProblemaIndependente` (Plano 3), `renderDiagramaSVG` (Plano 4), `esc()` (existente), classes CSS já existentes (`.card`, `.btn`, `.fb ok`/`.fb aj`, `.eyebrow`, `.sub`, `.spin`).

## Global Constraints

(herdadas dos planos anteriores, mais:)

- Este plano depende dos Planos 1-4 já implementados.
- Fluxo é sempre sequencial e unidirecional dentro da ficha (Tela 1 → 2 → 3), com botão de voltar só da Tela 2 pra Tela 1 — Tela 3 não tem "voltar" pra 2 porque, uma vez que o aluno começou o problema independente, forçá-lo a reler o resolvido quebraria o propósito de "resolver sozinho" (spec, Seção 8).
- Comportamento de erro segue exatamente a Seção 9 do spec: IA indisponível/JSON malformado → estado de retry sem erro técnico cru; retrieval sem material → aviso específico; nunca trava a tela.
- **Decisão de implementação tomada neste plano (não estava no spec):** a checagem "certo/errado" do problema independente compara **números extraídos** da resposta do aluno com o gabarito (tolerância de 0,01), porque os problemas são de aplicação numérica (cálculos fiscais/contábeis). Quando nenhum número é identificável em um dos dois lados, o app não arrisca um veredito errado — mostra "compare sua resposta com o gabarito" em vez de marcar certo/errado. Isso é mais simples e mais honesto do que um comparador de texto livre, que erraria com frequência.

- [ ] **Step 2: Adicionar a comparação numérica e a correção**

```js
function numerosDoTexto(texto){
  const limpo = String(texto).replace(/R\$/gi,'');
  const matches = limpo.match(/-?\d{1,3}(\.\d{3})*(,\d+)?|-?\d+(,\d+)?/g) || [];
  return matches.map(m=>parseFloat(m.replace(/\./g,'').replace(',','.'))).filter(n=>!isNaN(n));
}
function compararResposta(resposta, gabarito){
  const numsResp = numerosDoTexto(resposta);
  const numsGab = numerosDoTexto(gabarito);
  if(!numsResp.length || !numsGab.length) return null;
  const alvo = numsGab[numsGab.length-1];
  return numsResp.some(n=>Math.abs(n-alvo)<0.01);
}
function corrigirProblemaIndependente(){
  const resposta = document.getElementById('fia-resposta').value.trim();
  const resultado = compararResposta(resposta, fiaProblema.gabarito);
  const banner = resultado===true ? '<div class="fb ok"><b>Correto!</b></div>'
    : resultado===false ? '<div class="fb aj"><b>Incorreto.</b> Veja a correção abaixo.</div>'
    : '<div class="fb ok">Compare sua resposta com o gabarito e a correção abaixo.</div>';
  document.getElementById('fia-correcao').innerHTML = `${banner}
    <div style="border-left:4px solid var(--verde-ink);background:rgba(29,106,85,.08);padding:10px 14px;border-radius:6px;margin-top:10px">
      <p class="eyebrow">Gabarito</p><p class="mt1">${esc(fiaProblema.gabarito)}</p>
      <p class="eyebrow mt2">Correção detalhada</p><p class="mt1">${esc(fiaProblema.correcao_detalhada)}</p>
    </div>
    <button class="btn small mt2" onclick="irParaProblemaIndependente()">Gerar outro problema deste tópico</button>`;
}
```
